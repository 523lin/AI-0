# 青空计划

> 一个只管理“今天”的轻量个人看板。

## 代码仓库

本提交版已经整理好源码与三份核心文档。上传到 GitHub 或部门指定的远程仓库后，请把仓库链接补充在这里。

## 项目用途

“青空计划”面向希望把当天任务集中在一个屏幕里的个人用户。它只处理一条完整闭环：

**选择日期 → 输入或操作任务 → 看到当天的状态与完成度。**

它不追求“大而全”：没有账号、团队协作、消息通知或云端同步，打开本地文件即可使用。适合每天开始工作或学习前，快速把今天要做的事排清楚，并在一天结束时看到收尾结果。

## 主要功能

- **单日看板**：待做、进行中、已完成三栏，只显示所选日期的任务。
- **任务管理**：新建、编辑、删除、移动状态、直接完成；删除前有确认，保存后有反馈。
- **重要等级**：三颗星或两颗星，用来区分当天任务的优先顺序。
- **任务线索**：支持备注、标签，以及按日期切换、标签筛选；关键词搜索会弹出全日期结果框，逐条显示日期、状态、等级、标签和备注，按回车或点击放大镜触发；选择标签时看板按标签筛选，同时弹出该标签的全日期结果框。
- **当天进度**：展示完成比例和剩余数量；全部完成时显示收尾文案。
- **个人化设置**：头像上传、个性签名、浅色/深色主题。
- **重复任务提醒**：同一天添加同名任务时，先提示“新增失败”，再询问是否仍然添加。
- **视觉细节**：全站宋体、克制配色；深色模式有星空与流星，流星经过日程栏位时该栏位短暂透明。
- **响应式与本地保存**：适配桌面和窄屏，刷新后保留任务与偏好。

## 本地启动

1. 下载或解压完整项目文件夹，确保 `index.html`、`styles.css`、`app.js` 在同一层。
2. Windows 下双击 `启动青空计划.cmd`；也可以直接双击 `index.html`。
3. 推荐使用 Microsoft Edge 或 Google Chrome 打开。无需安装 Node.js，无需启动服务器。
4. 打开后即可新建当天任务；首次进入会写入几条合成示例任务。

注意：

- 不要只单独复制 `index.html`，否则样式和功能文件会缺失。
- 不要在压缩包的预览窗口中直接运行，先完整解压。
- 如果双击后被其他程序打开，右键 `index.html` → **打开方式** → 选择浏览器。

## 合成数据说明

首次打开且浏览器中没有本项目数据时，页面会写入 3 条示例任务，例如“整理今天的三个小目标”“复习数学·第三章函数”“完成英语单词打卡”，默认称呼为“同学”。

这些内容全部是**合成数据**，用于展示看板状态，不包含真实姓名、手机号、学号、成绩或其他未经授权的个人信息。示例任务可以直接编辑或删除。

任务、签名、头像和主题偏好只保存在当前浏览器的 `localStorage` 中，不会上传到服务器。

## 已知问题

- **仅本地单机**：没有账号、云端同步和多人协作；换浏览器、换电脑或清理浏览器数据后，原数据不会自动跟过去。
- **没有数据导入/导出**：目前不能把看板数据打包迁移到另一台设备。
- **头像存储有限**：头像会压缩后以 data URL 存入浏览器本地存储；文件过大或空间不足时可能保存失败，页面会给出提示。
- **浏览器差异**：本项目通过 `file://` 直接打开，部分浏览器对本地文件存储的处理不同，建议使用桌面版 Edge 或 Chrome。
- **皮肤功能未完成**：星星按钮目前只是入口，点击会提示“更多页面皮肤正在准备中，敬请期待”，没有更多皮肤。
- **功能范围有限**：暂不支持注册登录、团队协作、通知提醒、周期任务、月历总览、数据统计等。
- **测试方式**：当前以手动回归为主，尚未建立自动化测试套件；改动后需要按 `AGENTS.md` 的检查清单人工验证。

## 体验材料

- **在线体验链接**：暂无（尚未部署到公网）。
- **本地体验**：按上面的“本地启动”步骤运行即可。
- **提交前需补**：一段 1 分钟以内的功能操作录屏，或部署后的在线体验链接。

建议的录制顺序（控制在 1 分钟内）：

1. 打开页面，展示当天的三栏和示例任务。
2. 新建一条任务，设置标签和重要等级，保存。
3. 把一条任务移到进行中并完成，展示进度变化。
4. 输入关键词或选择一个标签，展示对应的全日期结果框与任务信息。
5. 点击签名句子修改签名，切换深色模式。
6. 刷新页面，展示数据仍然保留。

## 协同复盘

这个作品由我提出目标和验收标准，AI 帮我把“只做单日看板”的边界落成页面结构、交互和可运行代码，也补足了本地数据迁移、重复任务确认、窄屏布局和深色流星等细节。我负责范围和取舍：不做复杂系统，保留克制的蓝白与宋体，不把占位皮肤写成已完成，不为动效牺牲可读性。每轮修改后，我在桌面和 320/390 宽度检查文案、刷新后的数据、弹窗、签名点击范围和主题切换。遇到过头像本地存储、嵌套弹窗、窄屏重叠和点击区域过大的问题；取舍是先保证本地可用与数据不丢，再打磨动效。
